## 通知规则总览

路径：**系统设置 → 通知规则**

系统通过「事件 x 通道」矩阵控制通知行为。每一行是一个工单事件，每一列是一个通道，勾选即启用。

| 事件 | 说明 | 默认站内 | 默认短信 | 默认企业微信 | 默认钉钉 | 默认飞书 |
|------|------|:--------:|:--------:|:------------:|:--------:|:--------:|
| 工单创建 | 新工单提交，通知管理员 | ✓ | | | | |
| 工单分配 | 分配给工程师，@ 对应工程师 | ✓ | ✓ | ✓ | ✓ | |
| 开始处理 | 工程师开始处理 | ✓ | | | | |
| 工单解决 | 工程师完成修复 | ✓ | ✓ | | | |
| 工单完结 | 用户确认已解决 | ✓ | | | | |
| 工单关闭 | 流程结束 | ✓ | | | | |
| 工单超时 | 超出时限，@ 对应工程师 | ✓ | ✓ | ✓ | ✓ | |

> 以上为默认值，部署后可在通知规则页面自由调整。

### IM 通道 @ 逻辑（企业微信 / 钉钉 / 飞书）

企业微信、钉钉、飞书三个 IM 通道采用一致的 @ 规则：

- **工单创建**：`@所有人`，提醒所有管理员有新工单（飞书自建应用模式除外，见飞书章节）
- **工单分配 / 工单超时**：`@指定工程师`，根据用户配置的 UserID 或手机号精准提醒
- **其他事件**：不 @，仅推送消息

各 IM 通道的 @ 字段优先级：

| 通道 | 第一优先级 | 兜底 |
|------|-----------|------|
| 企业微信 | 用户「企业微信UserID」字段 | 手机号（`mentioned_mobile_list`） |
| 钉钉 | 用户「钉钉userid」字段 | 手机号（`atMobiles`） |
| 飞书 | 用户「飞书user_id」字段 | 无兜底（仅按 user_id/open_id @） |

### 系统公告

在通知中心发布公告时，会自动 `@所有人` 推送到企业微信群。

## 短信配置

路径：**系统设置 → 集成配置 → 短信配置**

系统内置三种短信驱动：阿里云、腾讯云、自定义 HTTP 网关。选择服务商后填写凭证即可。

### 通用设置

| 设置项 | 说明 |
|--------|------|
| 启用短信 | 总开关，关闭后所有短信不发送 |
| 服务商 | `aliyun` / `tencent` / `custom` |
| 签名名称 | 短信签名（如「IT 服务台」），需在服务商后台审批通过 |

短信模板代码在 `config/services.php` 的 `sms.templates` 节定义，按事件类型映射到服务商的模板 ID。部署时需在各服务商后台创建对应模板并更新配置。

### 阿里云短信

1. 登录 [阿里云短信控制台](https://dysms.console.aliyun.com/)
2. 创建 AccessKey（建议使用 RAM 子账号，仅授予短信发送权限）
3. 申请短信签名并审批通过
4. 创建短信模板，记录模板 Code（如 `SMS_123456789`）
5. 在系统设置中填写：

| 设置项 | 对应阿里云字段 |
|--------|---------------|
| AccessKey ID | RAM 用户 AccessKey ID |
| AccessKey Secret | RAM 用户 AccessKey Secret |
| 签名名称 | 已审批通过的签名 |

### 腾讯云短信

1. 登录 [腾讯云短信控制台](https://console.cloud.tencent.com/smsv2)
2. 创建 API 密钥（SecretId / SecretKey）
3. 创建签名并审批通过
4. 创建正文模板，记录模板 ID
5. 创建应用，获取 `SdkAppId`
6. 在系统设置中填写：

| 设置项 | 对应腾讯云字段 |
|--------|---------------|
| AccessKey | API SecretId |
| SecretKey | API SecretKey |
| 签名名称 | 已审批通过的签名 |
| SDK App ID | 短信应用的 SdkAppId |

### 自定义短信网关

适用于单位自建短信服务或第三方短信平台（非阿里云/腾讯云）。

| 设置项 | 说明 |
|--------|------|
| API 地址 | 短信网关的 HTTP 接口 URL |
| 请求方法 | `POST`（默认）或 `GET` |
| API Key | 如需 Bearer 认证则填写 |

请求体为 JSON 格式，系统会自动附带以下字段：

```json
{
  "phone": "13800138000",
  "template": "SMS_CREATED",
  "content": "【IT 服务台】工单工单分配，编号：N20260716001，请登录系统查看详情。",
  "params": "..."
}
```

如果短信网关需要不同的参数名，可在 `config/services.php` 的 `sms.custom.default_params` 中配置固定参数。

### 短信测试

在短信配置页面底部可输入手机号发送测试短信，验证配置是否正确。

### 报修人短信（受理通知 + 满意度调查）

路径：**系统设置 → 集成配置 → 短信配置 → 报修人短信**

上面各节描述的短信属于「内部通知」，按事件×通道矩阵发给管理员 / 工单管理员 / 工程师。**报修人短信**是面向报修人（工单提交者）的独立短信通道，**不受事件×通道矩阵控制**，由本区域两个独立开关分别管理。整单生命周期内向报修人最多发送两条短信：

| 短信 | 触发时机 | 开关 | 防重标记 |
|------|----------|------|----------|
| **受理通知** | 工单受理时（创建即分配，或工程师自行接单）发送一次 | `creator_sms_enabled` | `sms_acceptance_sent_at` |
| **满意度调查** | 工单完结时发送一次 | `creator_survey_enabled` | `sms_survey_sent_at` |

两个开关均**默认关闭**，开启后只对之后新建 / 流转的工单生效，不影响存量工单，也互不影响。

#### 报修人手机号来源

按以下优先级取号，取到第一个非空即用：

1. 工单的联系电话字段 `contact_phone`
2. 报修人账号的手机号（创建人 `User.phone`）

若两者都为空则不发送（记录日志），不会报错。

#### 短信模板与占位符

在短信配置页可直接编辑三套模板，保存后立即生效。支持以下占位符，发送时自动替换：

| 占位符 | 含义 | 受理模板 | 满意度模板 |
|--------|------|:--------:|:----------:|
| `{系统名称}` | 系统设置中的系统名称 | ✓ | ✓ |
| `{工程师电话}` | 接单工程师的手机号 | ✓ | |
| `{预约时间}` | 工单预约上门时间 | ✓ | |
| `{工单编号}` | 工单编号 `ticket_no` | ✓ | ✓ |

- **受理通知**按「有无预约时间」分两套模板：有预约时用「受理通知（有预约时间）」，无预约时用「受理通知（无预约时间）」。
- 工程师电话来自接单工程师的手机号；若未接单（无 `assignee_id`），则不发受理通知。

> **阿里云 / 腾讯云用户注意**：与内部短信一样，云端实际发送的文案以服务商控制台中**已审核通过的模板**为准，本地编辑的文案仅供对照。自定义网关模式下，本地文案直接生效。

#### 满意度回复回写（上行回调）

开启满意度调查后，报修人收到短信可回复 `1`（满意）或 `0`（不满意），系统自动把评价回写到对应工单。该能力依赖短信服务商的**上行回复回调（Mo 回调）**，需在服务商后台完成一次配置：

1. 在服务商后台找到「上行短信回复 / 回调地址 / Mo 回调」配置项
2. 将回调地址填为：
   ```
   http(s)://你的域名/sms/reply
   ```
   （其中域名取自「系统设置 → 系统访问地址」，路由 `/sms/reply` 已默认排除 CSRF 校验）
3. 系统按当前服务商**自动适配**回调字段，无需手动映射：

   | 服务商 | 手机号字段 | 内容字段 |
   |--------|-----------|----------|
   | 阿里云 | `phone_number` | `content` |
   | 腾讯云 | `PhoneNumber` | `ReplyContent` |
   | 自定义 | `phone`（可在设置页改 `sms_reply_phone_field`） | `content`（可改 `sms_reply_content_field`） |

4. 回调到达后，系统按手机号匹配**最近一条已发满意度调查且尚未回复的工单**，写入 `sms_satisfaction` 与 `sms_satisfaction_at`。

- 回复内容识别：`1` 或「满意」→ 满意；`0` 或「不满意」→ 不满意；其它内容视为无效回复，不回写但记录日志。
- 为避免服务商反复重试，即便匹配失败也返回 HTTP 200。
- **未配置回调**时短信仍能正常发送，只是无法自动回写评价，工单详情页会一直显示「未回复」。

#### 在工单详情页查看评价

工单发过满意度调查短信后，详情页底部会出现「报修人评价」区块，显示：

- 评价结果：满意（绿）/ 不满意（红）/ 未回复（灰）
- 调查发送时间，以及回复时间（已回复时）

## 企业微信配置

路径：**系统设置 → 集成配置 → 企业微信通知**

系统支持两种推送模式，可随时切换。切换后需重新勾选「启用」开关并保存。

### 模式对比

| 项目 | 群机器人 Webhook | 自建应用 |
|------|------------------|----------|
| **消息触达** | 仅企业微信 App 内可见 | 可直达个人微信「微信插件」 |
| **配置难度** | 低，仅需 Webhook 地址 | 中，需 CorpID + Secret + AgentID + 可信 IP |
| **域名/备案要求** | 无 | 需已备案域名（备案主体与企业一致或关联） |
| **@ 指定用户** | 支持（UserID 或手机号） | 支持（UserID 作为 touser） |
| **消息格式** | 纯文本（Text） | 纯文本（Text） |
| **适用场景** | 快速接入、内部群通知 | 需要消息直达个人微信 |

> **重要**：无论使用哪种模式，保存配置后必须确认「启用」开关已勾选。如果测试消息能收到但工单通知发不出来，通常是启用开关未打开。

### 群机器人模式

最简单的接入方式，适合快速试用。

**配置步骤：**

1. 在企业微信群聊中点击右上角 `...` →「群机器人」→「添加机器人」
2. 给机器人取个名字（如「工单通知」），点击添加
3. 复制生成的 Webhook 地址：
   ```
   https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxxxxxxx-xxxx-xxxx
   ```
4. 在「系统设置 → 企业微信通知」中：
   - 确认推送模式选「群机器人 Webhook」
   - 粘贴 Webhook 地址
   - **勾选「启用」**
   - 点击「保存配置」
5. 点击「发送测试」验证是否收到消息

**局限：** 群机器人消息不会同步到个人微信。成员在个人微信中只能看到一个提醒，消息内容被锁在企业微信 App 内。如果需要消息直接显示在个人微信中，请使用自建应用模式。

### 自建应用模式

消息可直达个人微信「微信插件」，成员无需打开企业微信 App 即可查看。

**配置步骤：**

1. 登录 [企业微信管理后台](https://work.weixin.qq.com/wework_admin/frame)
2. 进入「应用管理」→「自建」→「创建应用」
3. 设置应用名称（如「工单系统」）和可见范围（目标部门或全员）
4. 获取以下三项凭证：

   | 凭证 | 获取位置 |
   |------|----------|
   | **CorpID**（企业ID） | 「我的企业」→「企业信息」→「企业ID」 |
   | **Secret**（应用密钥） | 应用详情页 →「Secret」→ 点击查看（仅显示一次） |
   | **AgentID**（应用ID） | 应用详情页顶部的数字 |

5. 配置企业可信 IP：应用详情页 →「开发者接口」→「企业可信IP」→ 添加服务器出口公网 IP
6. 确保成员已在个人微信中关注企业的「微信插件」（管理后台 →「我的企业」→「微信插件」可查看引导方式）
7. 在「系统设置 → 企业微信通知」中：
   - 切换推送模式到「自建应用」
   - 填入 CorpID、Secret、AgentID
   - **勾选「启用」**
   - 点击「保存配置」
8. 点击「发送测试」验证是否收到消息

> **备案要求：** 配置可信 IP 前，企业微信可能要求先设置「可信域名」，且域名的 ICP 备案主体必须与当前企业主体相同或有关联关系。未备案域名无法通过校验。

### 用户 UserID 配置（@ 提醒）

工单分配和超时通知支持 @ 指定工程师。系统按以下优先级匹配：

1. **企业微信 UserID**（最精确，推荐）
2. **手机号**（兜底，需与企业微信绑定的手机号一致）

**UserID 的获取方式：**

企业微信群主或管理员在企业微信管理后台「通讯录」中，点开成员详情，看到的**「账号」**字段就是 UserID。不是昵称，也不是姓名。

**配置方式：**

1. 进入「用户管理」→ 编辑对应用户
2. 在「联系信息」区域找到**「企业微信UserID」**字段
3. 填入从企业微信获取的 UserID
4. 保存

> 如果用户没填 UserID 但填了手机号，系统会用手机号通过 `mentioned_mobile_list` @ 该成员。两种方式可以共存，互不影响。

### SSL 证书

企业微信 API 使用 HTTPS，PHP 需要配置 CA 证书才能验证连接。系统提供两种方式：

**方式一：页面上传（推荐）**

1. 从 https://curl.se/ca/cacert.pem 下载最新的 `cacert.pem`
2. 在「系统设置 → 企业微信通知」底部的 SSL 证书区域点击「上传」
3. 选择下载的 `cacert.pem` 文件
4. 上传后系统自动启用 HTTPS 验证

**方式二：关闭验证（仅限测试环境）**

在 SSL 证书区域关闭「验证 HTTPS 证书」开关。系统会显示安全风险提醒。**生产环境切勿使用。**

### 系统访问地址

路径：**系统设置 → 系统设置 → 系统访问地址**

企业微信通知中的工单链接使用此地址。请填写实际可访问的地址（含端口），例如：

```
http://192.168.1.100:8099
https://workorder.example.com
```

如果不填写，链接会默认指向 `http://localhost`，手机端无法打开。

## 钉钉配置

路径：**系统设置 → 消息设置 → 钉钉**

钉钉支持两种推送模式，与「系统访问地址」和「SSL 证书」配置（与企业微信共用）配合使用。

### 钉钉模式对比

| 项目 | 自定义机器人 Webhook | 工作通知（企业内部应用） |
|------|----------------------|--------------------------|
| **消息触达** | 仅钉钉群内可见 | 直达个人钉钉 |
| **配置难度** | 低，仅需 Webhook 地址 + 加签 secret | 中，需 AppKey + AppSecret + AgentId |
| **@ 指定用户** | 支持（userid 或手机号） | 支持（userid_list） |
| **@ 所有人** | 支持（isAtAll） | 支持（to_all_user） |
| **消息格式** | 文本（Text）/ Markdown | 文本（Text，Markdown 降级为纯文本） |
| **适用场景** | 快速接入、群内通知 | 需要消息直达个人钉钉 |

> 无论使用哪种模式，保存配置后必须确认「启用」开关已勾选。

### 钉钉自定义机器人模式

**配置步骤：**

1. 在钉钉群聊中点击右上角 `...` →「群助手」→「添加机器人」→选择「自定义」
2. 安全设置推荐选择「加签」，复制生成的 **secret**（SEC 开头）
3. 复制机器人的 **Webhook 地址**：
   ```
   https://oapi.dingtalk.com/robot/send?access_token=xxxxxxxx
   ```
4. 在「系统设置 → 钉钉」中：
   - 确认推送模式选「自定义机器人 Webhook」
   - 粘贴 Webhook 地址
   - 填入加签 secret（强烈推荐，防止地址被盗用）
   - **勾选「启用」**
   - 点击「保存配置」
5. 点击「发送测试」验证是否收到消息

### 钉钉工作通知模式

消息直达个人钉钉，适合需要精准通知到指定工程师的场景。

**配置步骤：**

1. 登录 [钉钉开发者后台](https://open-dev.dingtalk.com/)
2. 创建「企业内部应用」，获取以下凭证：

   | 凭证 | 获取位置 |
   |------|----------|
   | **AppKey** | 应用详情页 →「基础信息」 |
   | **AppSecret** | 应用详情页 →「基础信息」（仅显示一次） |
   | **AgentId** | 应用详情页顶部 |

3. 申请权限：「通讯录管理」「企业内部机器人」「工作通知」等（工作通知需开通「消息通知」权限）
4. 在「系统设置 → 钉钉」中：
   - 切换推送模式到「工作通知（企业内部应用）」
   - 填入 AppKey、AppSecret、AgentId
   - **勾选「启用」**
   - 点击「保存配置」
5. 点击「发送测试」验证是否收到消息

> 工作通知模式下，access_token 会自动缓存（提前 200 秒过期），token 失效时自动清除缓存重试一次。

### 钉钉 userid 配置（@ 提醒）

工单分配和超时通知支持 @ 指定工程师。在「用户管理 → 编辑用户」中填写用户的**「钉钉userid」**字段。

钉钉 userid 的获取方式：在钉钉管理后台「通讯录」中，成员详情页的「员工账号」即为 userid。若未填写 userid 但填了手机号，系统会用手机号通过 `atMobiles` @ 该成员。

## 飞书配置

路径：**系统设置 → 消息设置 → 飞书**

飞书支持两种推送模式。

### 飞书模式对比

| 项目 | 自定义机器人 Webhook | 自建应用 |
|------|----------------------|----------|
| **消息触达** | 仅飞书群内可见 | 直达个人飞书（IM 消息） |
| **配置难度** | 低，仅需 Webhook 地址 + 加签 secret | 中，需 App ID + App Secret |
| **@ 指定用户** | 支持（open_ids） | 支持（user_id） |
| **@ 所有人** | 支持（is_at_all） | 不支持（需指定接收人） |
| **消息格式** | 文本（Text） | 文本（Text） |
| **适用场景** | 快速接入、群内通知 | 需要消息直达个人飞书 |

> 自建应用模式下没有 `@all` 语义，必须指定接收人。工单创建事件在自建应用模式下会提示需指定接收人，建议创建事件仍使用机器人模式。

### 飞书自定义机器人模式

**配置步骤：**

1. 在飞书群聊中点击「设置」→「群机器人」→「添加机器人」→选择「自定义机器人」
2. 如需安全校验，启用「签名校验」并复制 **secret**
3. 复制机器人的 **Webhook 地址**：
   ```
   https://open.feishu.cn/open-apis/bot/v2/hook/xxxxxxxx
   ```
4. 在「系统设置 → 飞书」中：
   - 确认推送模式选「自定义机器人 Webhook」
   - 粘贴 Webhook 地址
   - 填入签名校验 secret（可选，推荐）
   - **勾选「启用」**
   - 点击「保存配置」
5. 点击「发送测试」验证是否收到消息

### 飞书自建应用模式

消息直达个人飞书 IM。

**配置步骤：**

1. 登录 [飞书开放平台](https://open.feishu.cn/)，创建「自建应用」并发布到企业
2. 获取以下凭证：

   | 凭证 | 获取位置 |
   |------|----------|
   | **App ID** | 应用「凭证与基础信息」页（cli_ 开头） |
   | **App Secret** | 应用「凭证与基础信息」页 |

3. 开通权限：`im:message`（发送消息）、`contact:user.base`（获取用户）等
4. 在「系统设置 → 飞书」中：
   - 切换推送模式到「自建应用消息」
   - 填入 App ID、App Secret
   - **勾选「启用」**
   - 点击「保存配置」
5. 点击「发送测试」验证是否收到消息

> 自建应用模式下，tenant_access_token 会自动缓存。消息通过 `/open-apis/im/v1/messages` 按 `user_id` 逐人发送，因此必须在用户管理中填写接收人的飞书 user_id，否则无法送达。

### 飞书 user_id 配置（@ 提醒）

在「用户管理 → 编辑用户」中填写用户的**「飞书user_id」**字段。飞书 user_id 可在飞书开放平台「通讯录」中查看，或通过 `contact:user.base` 权限查询。

## 常见问题

### 测试消息能收到，但工单通知发不出来

检查推送通道是否已启用。早期版本存在 boolean 配置比较 bug，如仍有问题请确认代码已更新到最新版本。在「系统设置 → 企业微信通知」页面确认对应模式的「启用」开关已勾选并保存。

### 企业微信自建应用报 `60020` 或 `not allow to access from your ip`

服务器出口 IP 未加入企业微信应用的可信 IP 列表。在管理后台 → 应用详情 →「企业可信IP」中添加服务器公网 IP。

### 企业微信自建应用报 `invalid corpid` 或 `40001`

CorpID 或 Secret 填写错误，或者 Secret 已被重置。检查凭证是否正确，必要时在管理后台重置 Secret 后更新配置。

### cURL error 60: SSL certificate problem

PHP 未配置 CA 证书。在企业微信配置页面上传 `cacert.pem`，或参考上方 SSL 证书章节。

### 工单地址显示为数字（如「2」而不是「2教」）

工单的 building 字段存储的是地址管理表（locations）的 ID，系统会自动查询完整楼名。如果地址显示不正确，请检查「地址管理」中的楼栋数据是否完整。

### @ 提醒不生效

1. 确认用户已填写企业微信 UserID（用户管理 → 编辑用户）
2. 确认 UserID 正确（是成员的「账号」不是昵称）
3. 如果用手机号 @，确认手机号与企业微信绑定的手机号一致
4. 确认该成员在群机器人所在的群内（群机器人模式）或在应用可见范围内（自建应用模式）

### 短信发送失败

1. 检查系统设置 → 短信配置中的网关参数是否正确
2. 检查短信签名是否已审批通过
3. 检查通知规则中对应事件的「短信」通道是否开启
4. 查看 `storage/logs/laravel.log` 中的错误详情
5. 若是**报修人短信**不发：检查「短信配置 → 报修人短信」下的受理通知 / 满意度调查开关是否开启（它们独立于通知规则矩阵）

### 满意度回复无法回写 / 工单一直显示「未回复」

**前提**：满意度调查开关已开启、短信也发出去了，但报修人回复后工单状态没更新。

1. **服务商未配置上行回调**：最常见原因。需在阿里云 / 腾讯云 / 自定义网关后台把上行回复回调地址设为 `http(s)://你的域名/sms/reply`。未配置则回复根本到不了系统。
2. **回调地址外网不可达**：`/sms/reply` 必须能被服务商从公网访问。若系统仅内网 / 校内可访问，服务商会请求超时；可在服务器上 `curl http://127.0.0.1/sms/reply` 确认路由存在（应返回 JSON），再排查外网可达性。
3. **手机号匹配不上**：系统按回调中的手机号匹配「最近一条已发满意度调查且尚未回复的工单」。若报修人手机号与工单 `contact_phone` / 创建人手机号不一致，则匹配失败，日志记「短信回复未匹配到工单」。
4. **回复内容无法识别**：只识别 `1` /「满意」与 `0` /「不满意」，其它内容不回写（日志记「短信回复内容无法识别为满意度」）。
5. **字段映射问题**：自定义网关模式下，若服务商回调字段名非默认 `phone` / `content`，可在设置页用 `sms_reply_phone_field` / `sms_reply_content_field` 指定实际字段名。

> 即便匹配失败，系统也会返回 HTTP 200，避免服务商反复重试回调。排查时以服务端日志为准。

### 消息格式为卡片而非纯文本

系统统一使用纯文本（Text）格式发送企业微信消息，确保在个人微信中也能正常显示。如果仍有问题，请确认代码已更新到最新版本。

### 钉钉通知发不出来

1. 确认「系统设置 → 钉钉」中对应模式的「启用」开关已勾选
2. 确认通知规则中对应事件的「钉钉」通道已开启
3. 机器人模式：检查 Webhook 地址是否正确、加签 secret 是否匹配
4. 工作通知模式：检查 AppKey / AppSecret / AgentId 是否正确，查看 `storage/logs/laravel.log` 中 access_token 获取是否成功
5. 点击「发送测试」排查具体错误

### 钉钉工作通知报 `access_token` 相关错误

AppKey 或 AppSecret 不正确，或 token 已过期。系统会自动清除缓存重试一次，若仍失败请检查凭证。在保存配置时会自动清除 token 缓存，重新获取。

### 飞书自建应用提示「需指定接收用户」

飞书自建应用模式没有 `@all` 语义。工单创建事件触发时，如果通知规则中飞书通道开启但接收人为空（即所有管理员都未填写飞书 user_id），系统会返回此提示。建议工单创建事件关闭飞书通道，或在用户管理中为相关管理员填写飞书 user_id。

### 飞书通知发不出来

1. 确认「系统设置 → 飞书」中对应模式的「启用」开关已勾选
2. 确认通知规则中对应事件的「飞书」通道已开启
3. 机器人模式：检查 Webhook 地址和签名 secret
4. 自建应用模式：检查 App ID / App Secret，确认应用已开通 `im:message` 权限，确认接收人已填写飞书 user_id
5. 点击「发送测试」排查具体错误
